# text-tree 2.0.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Split `text-tree` into a zero-dependency core plus a `text-tree-parsed` module built on `name-parser-api` 5.0.0, and bring the build's dependencies and plugins up to date.

**Architecture:** A Maven reactor with parent `org.gbif:text-tree-parent`. The core module keeps the `org.gbif:text-tree` coordinates and loses every runtime dependency. A new `org.gbif:text-tree-parsed` module holds the name-parser-backed variant in a new package `org.gbif.txtree.parsed`, and takes the `NameParser` from the caller so it never depends on an implementation. Both modules compile at release 17.

**Tech Stack:** Java 17, Maven 3.9, JUnit Jupiter 6, `org.gbif:name-parser-api` 5.0.0.

**Spec:** `docs/superpowers/specs/2026-08-21-text-tree-2.0.0.md`

## Global Constraints

- Both modules compile at `maven.compiler.release` = **17**. Nothing may require a newer JDK.
- `org.gbif:text-tree` must have **zero** `compile`/`runtime` scope dependencies when done.
- Neither module may depend on `org.gbif.nameparser:name-parser-rust` in any scope, nor on `org.gbif:name-parser`.
- `org.gbif:text-tree` keeps its groupId/artifactId so existing consumer poms need no edit.
- Project version is `2.0.0-SNAPSHOT` throughout; the actual release is cut by `maven-release-plugin` afterwards.
- Maven plugins use the latest **stable** line — do not adopt any `4.0.0-beta-*` plugin release.
- Run `mvn test` from the repo root after every task. It must pass before you commit.

### Task 4: Introduce the `TreeNodeFactory` SPI

The parsed variant is about to live in another module, so it needs a supported way to build its own
node type from a parsed line. Today that is the private `parse(Reader, Consumer<TreeLine>,
BiFunction<Long,Matcher,T>)`, whose `Matcher` parameter would leak regex group indices into the
public API. Replace it with a record and a functional interface, and widen `TreeNode` to public so
a subclass can live in another package.

The factory also receives the node's parent, because `text-tree-parsed` must inherit the `CODE`
info key down the tree (spec D7) and a stateless factory beats one that carries a hidden stack.
That means `Tree.parse` has to resolve the parent *before* building the node rather than after.

This task is a pure refactor: `Tree.parsed` still exists, still uses name-parser 4.0.0, and every
existing test still passes untouched.

**Files:**
- Create: `src/main/java/org/gbif/txtree/TreeNodeData.java`
- Create: `src/main/java/org/gbif/txtree/TreeNodeFactory.java`

- Modify: `src/main/java/org/gbif/txtree/Tree.java`
- Test: `src/test/java/org/gbif/txtree/TreeTest.java`

**Interfaces:**
- Consumes: `Tree.trimToNull` from Task 3.
- Produces, all used by Task 6:
  - `public record TreeNodeData(long id, String name, String rank, boolean extinct, boolean basionym, boolean homotypic, boolean provisional, Map<String,String[]> infos, String comment)`

```java
/**
 * Builds a concrete node from the components of one parsed tree line.
 * Implementations may reject a line by throwing {@link IllegalArgumentException}.

@FunctionalInterface
public interface TreeNodeFactory<T extends TreeNode<T>> {

  /**
   * @param data   the components of the line being read
   * @param parent the node this one hangs under, or null when it sits at the root level. Lets a
   *               node inherit from its ancestors without the factory holding state of its own.
   *               For a synonym this is the accepted name it is nested under.
   */

}
```

- [ ] **Step 6: Write the fake parser the tests drive**

`text-tree-parsed/src/test/java/org/gbif/txtree/parsed/FakeNameParser.java`. A real parser makes the
three `ParseResult` branches awkward to trigger on demand; this one makes each reachable from a
fixture name. It deliberately reports every parsed name as `UNRANKED` so a test can prove that
`ParsedTreeNode` writes the tree's own rank back, and records the code it was handed so a test can
prove the code reaches the parser at all.

```java
package org.gbif.txtree.parsed;

import org.gbif.nameparser.api.NameParser;
import org.gbif.nameparser.api.NameType;
import org.gbif.nameparser.api.NomCode;
import org.gbif.nameparser.api.ParseResult;
import org.gbif.nameparser.api.ParsedName;
import org.gbif.nameparser.api.Rank;

import java.util.ArrayList;
import java.util.List;

/**
 * A NameParser stand-in returning each of the three ParseResult variants on demand, so the mapping
 * into ParsedTreeNode can be tested without depending on a real parser implementation.
 *
 * <ul>
 *   <li>a name starting with {@code BOLD:} yields an Unparsable result</li>
 *   <li>a name ending in {@code " sp."} yields an Informal result</li>
 *   <li>anything else yields a Parsed result, always reporting rank UNRANKED</li>
 * </ul>
 */
class FakeNameParser implements NameParser {

  /** The code handed to each call, in call order. May contain nulls. */
  final List<NomCode> codesSeen = new ArrayList<>();

  @Override
  public ParseResult parse(String scientificName, String authorship, Rank rank, NomCode code) {
    codesSeen.add(code);
    if (scientificName.startsWith("BOLD:")) {
      return new ParseResult.Unparsable(NameType.PLACEHOLDER, null, scientificName);
    }
    if (scientificName.endsWith(" sp.")) {
      String genus = scientificName.substring(0, scientificName.indexOf(' '));
      return new ParseResult.Informal(genus, Rank.GENUS, Rank.SPECIES, null, null);
    }
    ParsedName pn = new ParsedName();
    pn.setType(NameType.SCIENTIFIC);
    pn.setRank(Rank.UNRANKED); // deliberately ignores the rank passed in
    pn.setUninomial(scientificName);
    return new ParseResult.Parsed(pn);
  }
}
```

Note the `BOLD:` marker rather than a leading `?`: `?` is the TextTree provisional prefix and would
be stripped off the name by the line parser before the name parser ever sees it.

```java
package org.gbif.txtree.parsed;

import org.gbif.nameparser.api.NomCode;
import org.gbif.nameparser.api.ParseResult;
import org.gbif.nameparser.api.ParsedName;
import org.gbif.nameparser.api.Rank;
import org.gbif.txtree.TreeNode;
import org.gbif.txtree.TreeNodeData;

import java.util.Locale;
import java.util.Objects;

/**
 * A node in a taxonomic tree backed by the result of running its name through a
 * {@link org.gbif.nameparser.api.NameParser}.
 */
public class ParsedTreeNode extends TreeNode<ParsedTreeNode> {

  /** The full three way parse result for {@link #name}. Never null. */
  public final ParseResult result;

  /**
   * The structured name. Null only for a {@link ParseResult.Unparsable} result — an
   * {@link ParseResult.Informal} result contributes its rebuilt taxon anchor, matching the
   * type=INFORMAL ParsedName that the 4.x Java parser returned instead of throwing.
   */
  public final ParsedName parsedName;

  /**
   * The nomenclatural code in scope for this name: its own {@code CODE} info if it declared one,
   * otherwise the one inherited from its parent. Null when the tree declares none.
   */
  public final NomCode code;

  public ParsedTreeNode(TreeNodeData data, Rank rank, NomCode code, ParseResult result) {
    super(data.id(), data.name(), rankName(rank), data.extinct(), data.basionym(),
        data.homotypic(), data.provisional(), data.infos(), data.comment());
    this.code = code;
    this.result = Objects.requireNonNull(result, "result required");
    this.parsedName = parsedNameOf(result, rank, code);
  }

  private static String rankName(Rank rank) {
    return rank == null || rank == Rank.UNRANKED ? null : rank.name().toLowerCase(Locale.ROOT);
  }

  private static ParsedName parsedNameOf(ParseResult result, Rank rank, NomCode code) {
    ParsedName pn = result instanceof ParseResult.Informal informal
        ? informal.toParsedName()
        : result.parsed().orElse(null);
    if (pn != null) {
      // keep the rank and code the tree declared, not whatever the parser inferred
      if (rank != null) {
        pn.setRank(rank);
      }
      if (code != null) {
        pn.setCode(code);
      }
    }
    return pn;
  }
}
```

`text-tree-parsed/src/main/java/org/gbif/txtree/parsed/ParsedTree.java`:

```java
package org.gbif.txtree.parsed;

import org.gbif.nameparser.api.NameParser;
import org.gbif.nameparser.api.NomCode;
import org.gbif.nameparser.api.ParseResult;
import org.gbif.nameparser.api.Rank;
import org.gbif.nameparser.util.RankUtils;
import org.gbif.txtree.Tree;
import org.gbif.txtree.TreeLine;
import org.gbif.txtree.TreeNodeData;
import org.gbif.txtree.TreeNodeFactory;

import java.io.IOException;
import java.io.InputStream;
import java.io.InputStreamReader;
import java.io.Reader;
import java.nio.charset.StandardCharsets;
import java.util.HashMap;
import java.util.Locale;
import java.util.Map;
import java.util.Objects;
import java.util.function.Consumer;

/**
 * Reads TextTree input into {@link ParsedTreeNode}s, running every name through a
 * {@link NameParser} supplied by the caller.
 *
 * <p>text-tree depends on {@code name-parser-api} only, never on an implementation: the current
 * one, {@code org.gbif.nameparser:name-parser-rust}, needs JDK 22+ and a per platform native jar,
 * which would otherwise be forced on every consumer. Wire it up yourself:
 *
 * <pre>{@code
 * Tree<ParsedTreeNode> tree = ParsedTree.parse(in, new NameParserRust());
 * }</pre>
 *
 * <p>The {@code CODE} info key sets the nomenclatural code for a name and is inherited by its
 * descendants, as in ChecklistBank. It disambiguates the ranks that exist once per code
 * ({@code division}, {@code section}, {@code series} and their sub/super forms) and is passed on
 * to the name parser.
 */
public final class ParsedTree {

  /** Recognised {@code CODE} values, lower cased. */
  private static final Map<String, NomCode> NOM_CODES = buildNomCodes();

  private static final String CODE_KEY = "CODE";

  private ParsedTree() {
  }

  public static Tree<ParsedTreeNode> parse(InputStream stream, NameParser parser) throws IOException {
    return parse(stream, parser, null);
  }

  public static Tree<ParsedTreeNode> parse(InputStream stream, NameParser parser,
                                           Consumer<TreeLine> listener) throws IOException {
    return parse(new InputStreamReader(stream, StandardCharsets.UTF_8), parser, listener);
  }

  public static Tree<ParsedTreeNode> parse(Reader reader, NameParser parser) throws IOException {
    return parse(reader, parser, null);
  }

  public static Tree<ParsedTreeNode> parse(Reader reader, NameParser parser,
                                           Consumer<TreeLine> listener) throws IOException {
    return Tree.parse(reader, listener, factory(parser));
  }

  /**
   * The node factory this class drives, exposed so it can be handed to
   * {@link Tree#parse(Reader, Consumer, TreeNodeFactory)} directly. Stateless and reusable.
   */
  public static TreeNodeFactory<ParsedTreeNode> factory(NameParser parser) {
    Objects.requireNonNull(parser, "parser required");
    return (data, parent) -> {
      NomCode code = code(data, parent);
      Rank rank = rank(data.rank(), data.id(), code);
      ParseResult result = parser.parse(data.name(), null, rank, code);
      return new ParsedTreeNode(data, rank, code, result);
    };
  }

  /**
   * The nomenclatural code in scope: this line's {@code CODE} info if it declares a recognised one,
   * else the parent's. An unrecognised value is ignored rather than rejected — ChecklistBank treats
   * it as a data issue, not a structural error.
   */
  static NomCode code(TreeNodeData data, ParsedTreeNode parent) {
    Map<String, String[]> infos = data.infos();
    String[] values = infos == null ? null : infos.get(CODE_KEY);
    if (values != null && values.length > 0 && values[0] != null) {
      NomCode code = NOM_CODES.get(values[0].trim().toLowerCase(Locale.ROOT));
      if (code != null) {
        return code;
      }
    }
    return parent == null ? null : parent.code;
  }

  /**
   * Resolves the rank as written in the tree to a {@link Rank} constant.
   *
   * <p>A rank that names a constant outright is taken verbatim, including an explicitly
   * code-qualified {@code [division zoology]} — deliberately not run through
   * {@link RankUtils#bestCodeCompliantRank}, which would rewrite it under a conflicting
   * {@code CODE}. Only the bare ambiguous form is resolved by the code in scope.
   *
   * @param value the verbatim rank, may be null
   * @param line  the line it was read from, used in the error message
   * @param code  the nomenclatural code in scope, may be null
   * @return the rank, or null if the line carried none
   * @throws IllegalArgumentException if the rank is unknown, or ambiguous with no code in scope
   */
  static Rank rank(String value, long line, NomCode code) {
    if (value == null) {
      return null;
    }
    String name = value.trim().toUpperCase(Locale.ROOT).replace(' ', '_');

    Rank explicit = rankOrNull(name);
    if (explicit != null) {
      return explicit;
    }

    // a bare ambiguous form such as [division]: only the code specific constants exist
    Rank botanical = rankOrNull(name + "_BOTANY");
    if (botanical != null) {
      String plain = name.toLowerCase(Locale.ROOT).replace('_', ' ');
      if (code == null) {
        throw new IllegalArgumentException("Ambiguous rank [" + value + "] on line " + line
            + ". It exists for both codes - declare a {CODE=...} or write it out as ["
            + plain + " botany] or [" + plain + " zoology].");
      }
      // bestCodeCompliantRank returns its input unchanged for a null code, hence the check above
      return RankUtils.bestCodeCompliantRank(botanical, code);
    }

    throw new IllegalArgumentException("Unknown rank [" + value + "] on line " + line);
  }

  private static Rank rankOrNull(String name) {
    try {
      return Rank.valueOf(name);
    } catch (IllegalArgumentException e) {
      return null;
    }
  }

  private static Map<String, NomCode> buildNomCodes() {
    // an acronym claimed by more than one code resolves to neither - PHYTO and PHYLO both report
    // ICPN today. Counted rather than hardcoded, so the entry appears by itself if that is fixed.
    Map<String, Integer> acronyms = new HashMap<>();
    for (NomCode c : NomCode.values()) {
      acronyms.merge(c.getAcronym().toLowerCase(Locale.ROOT), 1, Integer::sum);
    }

    Map<String, NomCode> map = new HashMap<>();
    for (NomCode c : NomCode.values()) {
      map.put(c.name().toLowerCase(Locale.ROOT), c);
      String acronym = c.getAcronym().toLowerCase(Locale.ROOT);
      if (acronyms.get(acronym) == 1) {
        map.put(acronym, c);
      }
    }

    // the spellings the ChecklistBank publishing guide and its users actually write
    map.put("botany", NomCode.BOTANICAL);
    map.put("bot", NomCode.BOTANICAL);
    map.put("plant", NomCode.BOTANICAL);
    map.put("plants", NomCode.BOTANICAL);
    map.put("zoology", NomCode.ZOOLOGICAL);
    map.put("zoo", NomCode.ZOOLOGICAL);
    map.put("animal", NomCode.ZOOLOGICAL);
    map.put("animals", NomCode.ZOOLOGICAL);
    map.put("bacteria", NomCode.BACTERIAL);
    map.put("bact", NomCode.BACTERIAL);
    map.put("prokaryotes", NomCode.BACTERIAL);
    map.put("virus", NomCode.VIRUS);
    map.put("viruses", NomCode.VIRUS);
    map.put("cultivars", NomCode.CULTIVARS);
    map.put("cultivated plants", NomCode.CULTIVARS);
    map.put("phyto", NomCode.PHYTO);
    map.put("phytosociology", NomCode.PHYTO);
    map.put("phylo", NomCode.PHYLO);
    map.put("phylocode", NomCode.PHYLO);
    map.put("phylogenetic", NomCode.PHYLO);
    return Map.copyOf(map);
  }
}
```

````markdown
The `CODE` info key sets the nomenclatural code for a name and is **inherited by its descendants**,

## Upgrading from 1.x

- `Tree.simple(..)`, `Tree.verify(..)` and printing are unchanged. If that is all you use, bump the
  version and delete any `org.gbif:name-parser` exclusion you had on text-tree.
- `Tree.parsed(in)` becomes `ParsedTree.parse(in, parser)` in the new `text-tree-parsed` artifact,
  and `org.gbif.txtree.ParsedTreeNode` moves to `org.gbif.txtree.parsed.ParsedTreeNode`.
- A bare `[division]` now needs a nomenclatural code in scope, because `name-parser-api` 5.0.0
  split `Rank.DIVISION` into `DIVISION_BOTANY` and `DIVISION_ZOOLOGY`. Either declare a
  `{CODE=botany}` on the name or an ancestor, or write the rank out as `[division botany]` /
  `[division zoology]`. `[section]`, `[series]` and their sub/super forms already behaved this way,
  and now resolve from `CODE` too.
- A rank resolved from a code re-prints in its resolved form: `[division]` under `{CODE=botany}`
  comes back out as `[division_botany]`. The disambiguation is information the tree did not carry
  before.
- A line containing only whitespace is now skipped rather than failing the parse.
````
